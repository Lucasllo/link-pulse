## Phase Goal

> Goal da ROADMAP (literal; ainda não está no formato de user story): Um cliente cria links curtos (gerados ou com alias) e é redirecionado para a URL original a partir do Postgres, num repositório que builda igual no Windows e no Linux, com CI verde desde o início.

Este é um plano de **fechamento de gap** (`gap_closure: true`). Ele recupera a truth da 01-06 que falhou na verificação: a regra "a URL não pode apontar para o próprio encurtador" (T-06-03) dava para contornar. Também deixa o README e o threat model fiéis ao que o código de fato bloqueia.

## Gap de origem (01-VERIFICATION.md, frontmatter `gaps`)

- **Truth que falhou:** "URL que aponta para o host de linkpulse.base-url responde 400 com errors[] no campo url (01-06, mitigação T-06-03 contra loop de redirect)". Status `partial`.
- **Causa:** `LinkService.pointsToShortener` compara só `URI.getHost()` com `baseUrl().getHost()` via `equalsIgnoreCase`. O FQDN com ponto final (`localhost.`), os IPs de loopback (`127.0.0.1`, `[::1]`) e as formas numéricas que o navegador lê como loopback (`0x7f000001`) passam pelo `@HttpUrl` e pela checagem. Com isso, um único `POST {"url":"http://localhost.:8080/loop-a","alias":"loop-a"}` cria um link que redireciona para ele mesmo (CR-01).
- **Mesma raiz (WR-01):** uma `linkpulse.base-url` sem esquema faz `getHost()` devolver `null`, o que desliga a checagem em silêncio e gera `shortUrl` relativa.
- **README:** as linhas 131 e 180 afirmam uma garantia que o código não entrega.

   - senão, olhar o último rótulo (depois do último `.`). Ele "termina em número" se for só dígitos ASCII, ou `0x` seguido de zero ou mais dígitos hex.    - devolve `true` quando termina em número e o host inteiro não casa com `CANONICAL_IPV4`.

4. `static boolean isLoopback(String normalizedHost)`:
   - `localhost`, ou terminado em `.localhost` (RFC 6761 §6.3: o navegador resolve para loopback sem DNS);

   - host entre colchetes:
     - `InetAddress.getByName(normalizedHost)` seguido de `isLoopbackAddress() || isAnyLocalAddress()`;
     - `UnknownHostException` conta como `false`;
     - só host entre colchetes vai para o `InetAddress`: com colchetes, o JDK interpreta o literal IPv6 ou lança exceção, sem consultar DNS. Nomes nunca chegam ao resolvedor;
     - um IPv4-mapped (`[::ffff:127.0.0.1]`) volta como Inet4Address 127.0.0.1 e conta como loopback (ver o probe no `<context>`).
