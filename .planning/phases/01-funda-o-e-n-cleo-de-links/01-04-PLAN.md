**3. `AliasPolicy` (`dev.linkpulse.link`, D-05/D-07).**
- `public final class`, com `public static final String ALIAS_REGEX` igual a `^(?=.*[-_])[A-Za-z0-9_-]{4,32}$` e `private static final Pattern ALIAS_PATTERN`.
- Construtor `AliasPolicy(Collection<String> reserved)`, que guarda um `Set` imutável com os itens em minúsculas via `toLowerCase(Locale.ROOT)`.
- `matchesFormat(String)` usa `ALIAS_PATTERN.matcher(alias).matches()`.
- `isReserved(String)` compara `alias.toLowerCase(Locale.ROOT)` contra o set.
- `check(String alias)`:
  - formato inválido → `throw LinkProblems.invalidField("alias", "deve ter de 4 a 32 caracteres entre letras, dígitos, '-' e '_', com pelo menos um '-' ou '_'")`;
  - reservado → `throw LinkProblems.invalidField("alias", "é uma palavra reservada")`.
- Javadoc em pt-BR explicando que códigos gerados são só alfanuméricos e o alias exige `-`/`_`, então os espaços não se cruzam. O alias é case-sensitive no armazenamento e no lookup (D-06); só a comparação com reservados ignora a caixa.

**4. `ApplicationConfig`.** Adicionar `@Bean AliasPolicy aliasPolicy(LinkPulseProperties properties)`, que devolve `new AliasPolicy(properties.alias().reserved())`.

**5. `LinkProblems`.** Os dois métodos novos seguem o padrão dos existentes. Nunca ecoar SQL, nome de constraint nem mensagem de exceção.
- `aliasConflict(String alias)`: status 409 (`HttpStatus.CONFLICT`); type `/problems/alias-conflict`; title `Alias já existe`; detail `O alias '<alias>' já está em uso.`; propriedade `alias`.
- `invalidField(String field, String message)`: status 400; type `/problems/validation-error`; title `Requisição inválida`; detail `Um ou mais campos são inválidos.`; propriedade `errors` com `List.of(Map.of("field", field, "message", message))`. É o mesmo formato que o `GlobalExceptionHandler` da 01-06 vai usar para Bean Validation.

**6. `LinkService` (D-05/D-08).**
- O construtor passa a receber `(LinkRepository repository, CodeGenerator codeGenerator, AliasPolicy aliasPolicy, Clock clock)`. A 01-06 acrescenta `LinkPulseProperties`.
- Em `create`, com `alias = request.alias()`:
  - se `alias != null`: chamar `aliasPolicy.check(alias)`; se `repository.existsByCode(alias)`, lançar `LinkProblems.aliasConflict(alias)`;
  - em seguida `long id = repository.nextId()`, e `code` = alias quando informado, senão `codeGenerator.encode(id)`.
- Envolver o `saveAndFlush` em try/catch de `DataIntegrityViolationException e`:
  - se `alias != null && isCodeConflict(e)`, lançar `LinkProblems.aliasConflict(alias)` (corrida, D-08);
  - senão, relançar `e`. Código gerado colidindo é impossível por D-05, então seria bug e vira 500.
- `private static boolean isCodeConflict(DataIntegrityViolationException e)` percorre a cadeia `getCause()`. Retorna true se encontrar `org.hibernate.exception.ConstraintViolationException` com `getConstraintName()` igual (ignorando caixa) a `uk_links_code`, ou `java.sql.SQLException` com `getSQLState()` `23505` e mensagem contendo `uk_links_code`.
