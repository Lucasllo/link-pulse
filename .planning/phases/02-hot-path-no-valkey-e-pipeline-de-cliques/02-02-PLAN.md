## Phase Goal

> Goal da ROADMAP (literal; ainda não está no formato de user story): Redirects saem do cache Valkey e continuam funcionando se ele cair; cada clique vira um evento processado de forma assíncrona e idempotente no MongoDB, e o cliente consulta estatísticas confiáveis de cada link.

Este plano entrega o começo do "cada clique vira um evento": todo 302 (nunca HEAD) publica um evento num Redis Stream sem atrasar nem derrubar o redirect.

<objective>
Publicar cada clique no stream `lp:clicks` de forma não bloqueante (CLICK-01): executor com fila limitada e `MAXLEN ~`. O IP vira HMAC antes do XADD (CLICK-06), o Referer vira host (D-03) e HEAD não conta (REDIR-06). O fail-open pelo gate do Valkey, a prova do descarte contado com fila cheia e o `toString` mascarado ficam com a 02-03.

Purpose: o redirect nunca espera o analytics, e nenhum dado pessoal cru sai do processo.
Output: `ClickPublisher`, `IpHasher`, `ReferrerNormalizer`, `ClickConfig`; `RedirectController` publicando só em GET; `linkpulse.ip-hash-key` obrigatória fora do dev; `ClickPublishIT`, `IpHasherTest`, `ReferrerNormalizerTest`.
</objective>

Decisões implementadas: **D-03** (referrer normalizado para o host, `"(direct)"` sem Referer; a normalização acontece já na ingestão, escolha de discricionariedade recomendada pela pesquisa), **D-08** (o código nunca lê headers de proxy; o IP vem só de `request.getRemoteAddr()`) e **D-10** (nenhuma tag com código, URL, IP ou user-agent).

Discricionariedade registrada aqui (Claude's Discretion "Privacidade e retenção"): hash = HMAC-SHA256 com chave de config sobre `"<dia UTC>|<ip>"`. A rotação diária não precisa de estado e permite "visitantes únicos por dia" depois. A chave é obrigatória: sem ela a aplicação não sobe (mesmo padrão da `linkpulse.base-url`). O profile dev e os ITs usam uma chave fixa, só de desenvolvimento.
